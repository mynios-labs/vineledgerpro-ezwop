Problem to solve now
We still cannot complete shipping end to end. We need rates, label purchase with idempotency, print, confirm shipped to eBay, void within window, reprint without recharging, webhooks to update timelines, and surfacing of errors in the same fixed size, scrollable modal format. Automation first, with manual overrides only when needed.

Implement exactly this and nothing else
A) Settings
• Add settings fields if missing: Shippo API key. Ship from address. Parcel presets. Signature required default. Default insurance amount. Auto buy labels flag default off. Auto mark shipped after purchase flag default off.

B) Rates
• Endpoint POST /api/orders/:id/rates. Use stored buyer address and settings. Return three cheapest rates with carrier, service, cost, ETA and include a full list for the drawer. Persist the chosen rate and append a “Rates quoted” timeline event. If address validation fails, return a structured error for the address correction modal.

C) Buy label with idempotency
• Endpoint POST /api/orders/:id/buy with {rateToken, insurance, signature}. If a label already exists for this order, return the existing label and tracking. Else purchase through Shippo and persist labelId, labelUrl, trackingNumber, carrier, service, costCents, purchasedAt. Set shippingStatus to Label purchased. Append “Label purchased” to the timeline.
• If the settings flag Auto buy labels is on, call buy immediately after a successful rates call.
• Never buy twice for the same order. Idempotency is required.

D) Print and confirm shipped
• Endpoint GET /api/orders/:id/label returns the saved labelUrl. Printing must never trigger a repurchase.
• Endpoint POST /api/orders/:id/confirm-shipped posts tracking to eBay. Idempotent. If already posted, return current state. On first post, set shippingStatus to Shipped and append “Tracking posted to eBay” and “Marked shipped.”
• If settings flag Auto mark shipped after purchase is on, call confirm-shipped immediately after a successful buy.

E) Void and reprint
• Endpoint POST /api/orders/:id/void-label allowed only within the carrier void window. On success persist refund info, clear labelId and tracking, set shippingStatus back to Unshipped, append “Label voided” and “Refund posted.”
• Reprint always uses GET /api/orders/:id/label. Never creates a new label.

F) UI wiring on existing Orders page
• Unshipped tab. Show preselected rate summary, Change options, Get rates, and Buy label if Auto buy is off.
• Label purchased tab. Show Print label and Confirm shipped.
• Shipped tab. Show tracking and timeline.
• Add a timeline drawer per order that shows Synced, Rates quoted, Label purchased, Tracking posted to eBay, Marked shipped, Webhook updates, Voided, Refund posted.

G) Webhooks and alerts
• Add Shippo webhook for tracking and refunds. Update status and append timeline events for in transit, out for delivery, delivered, exception, refund.
• Keep the in app alert badge for new paid orders. Also send the simple email you already use when a label becomes ready.

H) Error handling
• All new errors use the existing fixed width, scrollable modal pattern with full request and response bodies and a Copy all button. Reuse the tracer formatting.
